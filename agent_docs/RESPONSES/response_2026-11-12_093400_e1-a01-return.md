### Proven

- **Catalogue:** both shapes give 99 / 148 / 197 USD and identical proration, 10% coupon, and cancel/undo-by-API results. The single graduated price is simpler to operate (one item, one quantity), so I propose it provisionally until the portal probe.
- **Session exchange:** `generateLink` + `verifyOtp` creates a real session for an existing user with sign-up disabled, sends no email, and is single-use.
- **Cookie separation:** distinct cookie names isolate the two apps on one host; today's default names do not.
- **Logout:** after a provider-wide sign-out, `getUser()` rejects every session of that user immediately and refresh fails. No extra liveness helper is needed, and OwedBook's server-key use stays within D-01.
- **Residual:** the access token lives 3600 seconds, and the data API kept accepting an unexpired token after sign-out (watched for 14 seconds; the rest is computed from the expiry).
- **Email:** the project mailer accepted sign-in link requests for OWNER_1 and STORE_ADMIN at 09:28 on 12 November. Accepted is not delivered.

### Findings that change the design

- **Link generation creates users.** Called for an address with no identity, it created one despite sign-up being disabled. The handoff must load the user by ID first, and provisioning must use the explicit create call.
- **One live link per user.** A handoff kills a pending emailed sign-in link, and a new emailed link kills an in-flight handoff. Two simultaneous handoffs: one fails. I recommend accepting this with a "send a new link" page and one automatic restart; this needs Friday's decision.
- **Link generation starts the email throttle.** A link request within a minute of a handoff got a 429.
- **A link issued before sign-out still works after it.** Our pending handoff codes must be invalidated at logout.

The simple logout design passes; the session-family fallback is not triggered.
