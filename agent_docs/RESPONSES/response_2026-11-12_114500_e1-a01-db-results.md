### Findings for the hardening migration

- **Store admins can update any store column today.** The `businesses` UPDATE grant and the `business_update_admin` policy are both live, so the account link, status, NPI and Stripe customer ID are editable through the data API.
- **Residual grants everywhere.** `anon` and `authenticated` hold TRUNCATE, REFERENCES and TRIGGER on every table, including `accounts`, `subscriptions`, `user_data` and `audit_logs`. The data API cannot issue TRUNCATE, so this is not a live exposure, but it should be revoked.
- **New objects are open by default.** The schema's default privileges grant every new table and function to `anon` and `authenticated`. Every 007A migration must revoke explicitly on each object it creates; I have written that into the migration plan with a closing assertion.
- **Billing rows are readable by any store member.** `subscriptions` has a member-or-owner SELECT policy; the plan narrows it to owner-only.
- **No unique index on NPI alone**, only on the `(ncpdp, npi)` pair.
